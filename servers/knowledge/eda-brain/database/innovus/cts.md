# Clock Tree Synthesis Commands

## create_ccopt_clock_tree_spec

### Syntax
```tcl
create_ccopt_clock_tree_spec [-file filename]
                             [-name name]
                             [-integrated_clock_gating]
                             [-use_existing_clock_spec]
```

### Description
Generates a clock tree specification file for CCOpt (Clock Concurrent Optimization). This file defines the clock tree structure, constraints, and optimization targets.

### Arguments
| Option | Description | Default |
|--------|-------------|---------|
| `-file` | Output specification file name | cts.spec |
| `-name` | Name for the clock spec | - |
| `-integrated_clock_gating` | Include clock gating in spec | false |
| `-use_existing_clock_spec` | Use existing spec as base | false |

### Examples
```tcl
# Create basic clock spec
create_ccopt_clock_tree_spec -file cts.spec

# Create spec with clock gating
create_ccopt_clock_tree_spec -file cts.spec -integrated_clock_gating
```

## ccopt_design

### Syntax
```tcl
ccopt_design [-cts]
             [-postCTS]
             [-postRoute]
             [-hold]
             [-setup]
             [-incremental]
             [-report_only]
```

### Description
Performs Clock Concurrent Optimization (CCOpt) including clock tree synthesis, buffering, and timing optimization. This is the main CTS command in Innovus.

### Arguments
| Option | Description |
|--------|-------------|
| `-cts` | Run CTS only (no optimization) |
| `-postCTS` | Post-CTS optimization |
| `-postRoute` | Post-route optimization |
| `-hold` | Focus on hold fixing |
| `-setup` | Focus on setup fixing |
| `-incremental` | Incremental optimization |
| `-report_only` | Generate reports only |

### Examples
```tcl
# Full CCOpt flow
ccopt_design

# CTS only
ccopt_design -cts

# Post-CTS optimization
ccopt_design -postCTS

# Fix hold violations
ccopt_design -hold

# Setup optimization
ccopt_design -setup
```

## setCTSMode

### Syntax
```tcl
setCTSMode -mode value
```

### Description
Configures CTS behavior and optimization targets.

### Key Options
| Option | Description | Default |
|--------|-------------|---------|
| `-sink_type` | Sink type (register|macro|all) | all |
| `-route_type` | Routing type (route|trial|none) | route |
| `-route_top_priority` | Route clock nets first | true |
| `-route_leaf_priority` | Route leaf nets with priority | true |
| `-use_lib_max_fanout` | Use library max fanout | false |
| `-use_lib_max_cap` | Use library max capacitance | false |
| `-honor_net_route_rule` | Honor routing rules | true |

### Examples
```tcl
# Set CTS mode for high-performance design
setCTSMode -route_type route
setCTSMode -route_top_priority true
setCTSMode -use_lib_max_cap true
```

## set_ccopt_property

### Syntax
```tcl
set_ccopt_property property_name value [-clock clock_name]
```

### Description
Sets properties for CCOpt optimization.

### Common Properties
| Property | Description | Example |
|----------|-------------|---------|
| `target_max_trans` | Target max transition | `set_ccopt_property target_max_trans 0.1` |
| `target_skew` | Target skew | `set_ccopt_property target_skew 0.05` |
| `max_fanout` | Maximum fanout | `set_ccopt_property max_fanout 32` |
| `max_cap` | Maximum capacitance | `set_ccopt_property max_cap 0.5` |
| `insertion_delay` | Target insertion delay | `set_ccopt_property insertion_delay 0.2` |

### Examples
```tcl
# Set target skew for all clocks
set_ccopt_property target_skew 0.05

# Set max transition for specific clock
set_ccopt_property target_max_trans 0.1 -clock clk

# Set max fanout
set_ccopt_property max_fanout 32
```

## Clock Tree Specification File Format

### Example cts.spec
```tcl
# Clock tree specification
# Generated by create_ccopt_clock_tree_spec

# Clock root definition
ClockRoot {
    clk {
        MaxTran 0.1
        MaxSkew 0.05
        MaxFanout 32
        MaxCap 0.5
        InsertionDelay 0.2
    }
}

# Skew group definition
SkewGroup {
    clk {
        ClockRoot clk
        Targets [get_pins -of [get_cells -filter "is_register==true"] -filter "pin_direction==in"]
        TargetMaxTran 0.1
        TargetSkew 0.05
    }
}

# Clock gate group
ClockGateGroup {
    clk_gates {
        ClockRoot clk
        ClockGates [get_cells -filter "is_clock_gating==true"]
    }
}
```

## Complete CTS Flow
```tcl
# Pre-CTS setup
setCTSMode -route_type route
setCTSMode -route_top_priority true

# Set CCOpt properties
set_ccopt_property target_max_trans 0.1
set_ccopt_property target_skew 0.05
set_ccopt_property max_fanout 32

# Create clock spec
create_ccopt_clock_tree_spec -file cts.spec

# Run CTS
ccopt_design -cts

# Report clock tree
report_ccopt_clock_trees

# Post-CTS optimization
ccopt_design -postCTS

# Check timing
report_timing -max_points 10

# Save checkpoint
saveDesign cts.enc
```

## Common Errors

### Error: No clock roots defined
```
**ERROR: (CTS-1): No clock roots defined in specification
```
**Solution**: Define ClockRoot in cts.spec or check SDC constraints

### Error: Max transition violation
```
**ERROR: (CTS-2): Max transition target not achievable
```
**Solution**: Relax target_max_trans or use larger buffers

### Error: Skew target too tight
```
**ERROR: (CTS-3): Target skew cannot be achieved
```
**Solution**: Increase target_skew or check clock tree structure

## Best Practices
1. Define realistic skew and transition targets
2. Use library-recommended buffer cells
3. Consider clock gating integration
4. Run trial CTS before final implementation
5. Verify clock tree power consumption
6. Check for clock tree congestion
